# permission-gap —— 自走するエージェントを止めるものは 4 つあり、233 件のうち 124 件は自分で書いた防御だった

Claude Code を `/loop` で自走させている。呼び出しが拒まれても、モデルは文字列を 1 つ受け取って
先へ進むので、1 週間たつと「何に止められたのか」が誰にも分からない。だから数えた。
**セッション記録 335 ファイル・ツール結果 20,294 件・走査 3.0 秒・拒否 233 件**(2026-09-17・
1 プロジェクト・自分たちの記録)。

| 誰が止めたか | 件数 | 最も止まった形 | 打つ手 |
|---|---:|---|---|
| **自分で書いた PreToolUse フック** | **124** | `python - <heredoc>`(20) | 自分のコードなので直せる |
| **実行環境の許可の分類器** | **52** | `mcp__chrome-devtools__evaluate`(5) | 自分のものではない。ただし 86% は後で通っている(下記) |
| **許可リストが覆っていなかった** | **49** | `rm -rf <path>`(18) | 設定 1 行 |
| **人が「いいえ」を押した** | **8** | 5 つの形が 1 回ずつ | 会話する |

4 つはどれも、モデルには同じ種類の呼び出しに付いた同じ種類のエラーとして届く。記録から取れるのは
「失敗した回数」だけで、**その 1 つの数は 4 列のうち 3 回に 1 回しか正しい列を指さない**。
こちらの場合、**摩擦の最大の源は自分で書いた防御**であり、列を割るまでそれを知らなかった。

```
python permission_gap.py scan
python permission_gap.py scan --since 2026-09-01 --settings .claude/settings.json --json
```

Claude Code が `~/.claude/projects` に既に書いているセッション記録を読む。**標準ライブラリだけ・
読むだけ・何も書かない。**終了コード 0 = 走査した(見つかった件数は失敗ではない)/ 2 = 読む物が無い。

---

## 実行環境は 9 種類の理由を返し、52 件のうち 29 件は理由が付いていなかった

分類器の拒否の文には印が付く。15 日ぶんの内訳:

| 理由の文字列 | 回数 |
|---|---:|
| `Blocked by classifier`(印そのものが無い) | **29** |
| `[Self-Modification]` | 6 |
| `Stage 2 classifier error - blocking based on stage 1 assessment (usually transient)` | 5 |
| `[Create Public Surface]` | 4 |
| `[Out-of-Place Publication]` | 3 |
| `[External System Writes]` | 2 |
| `[Security Weaken]` / `[Remote Repoint]` / `[Auto-Mode Bypass]` | 各 1 |

9 種類のうち 6 種類は**同じ狙いの操作**に当たっている —— 自分の公開リポジトリに何かを出すことだ。
それが分かるには集計が要る。1 つのターンの中から見ると、無関係な 6 つの失敗に見える。

## 揺れ: 同じ形が 1,657 回通り、27 回拒まれた

この道具は呼び出しを**形**に縮める(`cd /x && python tools/gh_api.py post /r b.json` →
`python gh_api.py post <path>`)。そして「拒まれた形は一度でも通ったか」を見る。

| 形 | 拒否 | 通った | 拒んだ層 |
|---|---:|---:|---|
| `python - <heredoc>` | 27 | 1,657 | 4 層すべて |
| `python -c <code>` | 12 | 541 | フック・分類器・人 |
| `echo <arg>` | 14 | 554 | フック・分類器・許可リスト |
| `Edit .md` | 7 | 1,086 | フック・分類器 |
| `WebFetch booth.pm` | 5 | 15 | フック |

**同じ形で判定が変わるなら、それは規則ではなく賽である。**再試行するエージェントは頑固に見えるが、
実際には合理的に振る舞っている。逆の側にも名前を付けた —— **壁**(3 回以上拒まれ、一度も通っていない
形): `rm -rf <path>`(20)・`rm -rf <arg>`(9)・`powershell -NoProfile -Command <code>`(7)・
`curl -s <url>`(3)。この 4 つは決着している。書くのをやめればよい。

## 「分類器は迂回するもの」と書いた。時計を当てたら 63 件中 54 件が後で通っていた

上の表は「拒まれた回数」と「通った回数」を並べているが、**回数には向きが無い**。先週まで 100 回
通っていて以後ずっと拒まれている形と、1 回拒まれて叩き直したら通った形は、この表の上では
見分けが付かない。正反対の状況を 1 つとして読んでいた。そこで同じ記録に狭い問いを立て直した ——
**この拒否の「後」に、同じ形が一度でもきれいに返ってきたか。何分後か。**

冒頭の見出しの 5 時間後に測り直しているので、母数が違う。
ファイル 350・ツール結果 21,438 件・**拒否 258 件**。下の表は
`python permission_gap.py scan --dir <あなたのプロジェクトの記録フォルダ>` の
`AFTER THE REFUSAL` の節そのままで、走らせれば同じ 4 行があなたの記録で出る。
**このページの数字に読む値打ちがあるとすれば、その 1 点だけである。**

| 誰が止めたか | 拒否 | 後で同じ形が通った | 一度も通らず | 待ち 最短 / 中央 / 最長 |
|---|---:|---:|---:|---|
| 自分で書いた PreToolUse フック | 133 | 96(72%) | 37 | 0.0 / 2.5 分 / 3.1 日 |
| **実行環境の分類器** | **63** | **54(86%)** | **9** | 0.0 / **11.5 分** / 23.2 時間 |
| 許可リスト | 54 | 9(17%) | 45 | 0.1 / 0.3 分 / 1.4 日 |
| 人が「いいえ」を押した | 8 | 6(75%) | 2 | 1.0 / 17.1 分 / 11.3 時間 |

**「自分のものではない。迂回する」と書いた行が、いちばんよく通る行だった。**通らないのは
自分の許可リストのほうで、54 件のうち 45 件は窓の終わりまで拒まれたままである —— 誰も編集しない
設定は、そのままの形で残るからだ。**恒久的だと思って畳んだ層は大半が「待ち」で、設定 1 行だと
思っていた層のほうが、誰かがその 1 行を打つまで本当に止める。**

「とにかく叩き直せ」にならない理由が 2 つある。1 つ目、**63 件のうち 56 件は、拒まれる前にも
同じ形が通っている** —— つまりここで測ったものの多くは、上の「揺れ」を裏側から見たもので、
閉じた扉が開いたわけではない。2 つ目、**7 件はどんな形でも二度と試されていない。**この欄はまさに
そのために作った —— エージェントが「拒否」を「できない」と読んで仕事を捨て、記録の上では本物の壁と
区別が付かない。こちらはこれで、**外に出るはずだった 2 日分の成果が、送り直されないまま拒否の後ろに
留まっていた**。

本当に決着しているのは「壁」の一覧にある形のほうで、分類器が出しているのはちょうど 1 つ ——
`python gh_api.py post <path>`(2 日で 3 回拒否・一度も通っていない)。**時計を当てて分かったのは、
壁なのは層ではなく形だということである。**

## 36 回、拒否の 2 分以内に無関係な呼び出しが拒まれている

`collateral` として数える —— 同じセッションで、**別の**形が窓(既定 120 秒)の内側で拒まれた回数。
これは先に手で気づいた。拒否 → 直後に素の `grep` まで拒否 → 別の道具で同じ仕事をして回復、という順で
起きる。**36 は因果の証明ではなく、道具自身が出力にそう書く。**自分のフックのバグを探しに行く前に
見るべき数である。

## 0 で返ってきた計測と、それがなぜ発見なのか

この道具は拒否 1 件ごとに、自分の `permissions.allow` と突き合わせる —— **自分の設定が「はい」と
言っているのに拒まれた場合**を捕まえるためだ。こちらの結果は**許可ルール 3 本に対して 0 件**。
起きていないからではない(2 日で 5 回起きた)。頼りにしていた許可が、**設定ファイルではなく自分で
書いた設計文書の中にあった**からだ。計器に見えるのは設定だけである。

**文章の中にしか無い許可は実行されない。**それを受け入れるまでに 2 日で 5 回の試行を使った。この欄の
0 は、その事実のいちばん短い言い方だ。

## 主張できないこと

1. **拒否の当否は測れない。**何が拒まれたかを報告するだけで、拒んだのが正しかったかは言わない。
   フックの 124 件は大半がフックの仕事そのものである
2. **形は経験則である。**`cd` / `VAR=` / `sudo` の前置きを落とし、引用符でくるんだ塊とファイル名は
   `<arg>`、URL は `<url>`、ヒアドキュメントと `-c` の本体は切り、4 語で打ち切る。人が見れば別物の
   2 つが 1 つの形に落ちることがあるので、確かめる用に `--raw` を置いた
3. **4 層は文字列の分だけしか分けられない。**拒否の文の先頭で判定しているので、文言が変われば層は
   誤るのではなく**黙る**。これがいちばん知っておいてほしい壊れ方である
4. **セッション記録は完全な記録ではない。**モデルに届いたものしか入っていない。発行される前に
   止まった呼び出しは、数える対象として残らない
5. **grep で数えると 4.7 倍に膨らむ。**同じファイル群の中に「denied by the Claude Code auto mode
   classifier」という文は **242 回**現れ、拒否は **52 件**である。残りは、エージェントが自分の
   メモと課題表にその拒否を引用した文と、そのメモに対して自分でかけた grep の出力だ。この道具は
   `is_error` の付いた `tool_result` しか数えない。だからテストの 1 つは**自分たちの文章そのもの**で、
   それが数に入らないことを確かめている
6. **233 件のうち 82 件はサブエージェントの中で起きた。**セッション単位の画面では 1 件も見えない。
7. **「後で通った」は「再試行が効いた」ではない。**同じ**形**の呼び出しが後でエラー無しに返った、
   という意味でしかない。同じコマンドとは限らず、待ったから通ったことも誰も証明していない。
   1 回拒まれて 1,000 回通っている形は、数秒の待ちを示すが、その数秒に意味は無い。この欄は
   **「拒まれた」と「できない」が別の語である証拠**として読むもので、再試行の方針ではない

## 引数

| 旗 | 意味 |
|---|---|
| `--dir D` / `--file F` | 読む場所(既定 `~/.claude/projects`。`CLAUDE_CONFIG_DIR` に従う) |
| `--settings F` | `permissions.allow` を読む設定ファイル(複数可) |
| `--since` / `--until` | 日付で窓を切る |
| `--window N` | collateral の窓(秒。既定 120) |
| `--raw` | 拒まれたコマンドも出す(鍵の形の文字列は隠す) |
| `--json` | 機械可読。週ごとの集計に使う |

鍵に見える文字列(`ghp_…`・`sk-…`・`xox…`・長い 16 進)は印字の前に隠す。**貼る前に出力を読むこと。**
コマンドはその人のものであり、作りから安全なのは形の側だけである。

## 検査

```
python -m unittest test_permission_gap   # 75 件
python mutation_check.py                 # 33 通りわざと壊し、33 通り全部で落ちる
```

変異の script は道具を 33 通りに壊し、1 つでもテストが見逃せば失敗する。33 のうち何本かは、この道具が
実際にやった誤りだ —— `VAR="…/scratchpad"` の前置きをコマンドとして報告した件、ヒアドキュメントの
区切りをスクリプト名として吸い込んだ件、そして `cd *` の許可ルールが `cd` の後に連結した何もかもを
「覆っている」と数えて、見出しの数字を 76 件に膨らませた件である。

**Claude Code を自走させている方へ: あなたの 4 つの数はいくつですか。**走らせて、隠すべき所を隠して、
[4 つの数をこの議論に貼ってください](https://github.com/samuboon/claude-code-harness/discussions/3)。
こちらの数もそこに置いてあります(窓を広げたら 4 層の順位が入れ替わった話も)。
1 つのプロジェクトの記録は、まだ数ではありません。
