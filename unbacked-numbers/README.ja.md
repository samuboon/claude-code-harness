# unbacked-numbers —— このリポジトリの表紙は 110 個の数字を主張していて、その出典を 1 つも載せていない

1 週間のあいだに、この現場で 2 つのことが起きました。作業役のエージェントに GitHub の issue の 👍 を数えさせたら **153** と返ってきた —— スレッドの全リアクションを足した数で、`+1` は **149** でした。もう 1 つは、あるサービスの凍結の挙動を記憶から断言し、翌日に撤回したことです。

1 つ目のあとに書いた決まり —— *数字は出典に到達できるものだけ* —— は、規約ファイルの中の 1 文です。**文は何も検査しません。**これは検査します:

```bash
python unbacked-numbers/unbacked_numbers.py REPORT.md
python unbacked-numbers/unbacked_numbers.py REPORT.md --min 1 --drift 2
python unbacked-numbers/unbacked_numbers.py docs/ --format paste   # 件数だけ。パスも行の文字も出さない
```

文書を**引用**(```` ``` ```` の塊・引用行・インラインコード・`"..."`・`「...」`)と**地の文**に割り、**同じファイルのどの引用にも現れない数字**を地の文から拾って並べます。

**その数字が正しいかどうかは分かりません。**答えるのはもっと小さく、ほとんど無料な問いです ——「この文書は、読者に信じてくれと言っている数字の**根拠を自分で持っているか**」。数字をいくらでも流暢に作れるモデルが書いた報告に対しては、こちらの問いのほうが効きます。

---

## 実測(このリポジトリがいちばん悪く見える数字から)

```
python unbacked-numbers/unbacked_numbers.py README.md

110 unbacked numbers in 1 files
  near-miss (a quoted number is within 5%) : 0
  unbacked                                 : 107
  link-only (a URL on the line, no quote)  : 3
  below --min 10 (not counted)             : 18
  files that quote nothing at all          : 0
```

107 が素の findings で、3 つは引用の代わりにリンクが置かれている行にあります。その中には表紙の「実測(誇張なし)」の表の回数 —— あのページが信じてもらうために存在している部分の数字 —— が含まれます。根拠そのものは実在し、非公開の作業木の台帳にあります。**つまり文書の中には無い**わけで、初めて読む人にはそれらと作り話の数字の区別が付きません。日本語の表紙は 129 でした。リポジトリ全体では:

```
python unbacked-numbers/unbacked_numbers.py .

778 unbacked numbers in 31 files
  near-miss (a quoted number is within 5%) : 29
  unbacked                                 : 529
  link-only (a URL on the line, no quote)  : 220
  below --min 10 (not counted)             : 132
  files that quote nothing at all          : 8  (--strict to scan them)
```

`link-only` を別の列にしたのは、引用の代わりに差し出される物の筆頭がリンクだからです。**リンクは引用ではありません** —— 「この先にその数字がある」という約束です。

## 外している 3 つ(このリポジトリで測った値つき)

**1. いちばん売りにしたい「near-miss」の列が、ここでは 29 件中 29 件とも外れです。**引用された数字の 5% 以内に入る地の文の数字を「書き写しのずれ」として挙げます —— 元になった 153/149 の誤りがまさにこの形だったからです。この木では全部が雑音で、29 件すべてを読みました: 11 件はデータ表の順位の列(`abandoned-demand/MAP.md` の 95〜105 行目の順位が、引用された件数 100 の隣に並んでいる)、4 件は `tile-seam/README.md` の閾値の説明(*100% なら最悪の縁・100% に届かない 99% 以上*)、2 件は引用されたバイト値の隣にある 1 だけ大きいテクスチャの辺、**そして 12 件はこのファイルと英語版の中**です(下に出てくる年の範囲の上限が、少し上で引用した日付の 5% 以内に入る、等)。すでに `NEAR_MISS_FLOOR = 100` という床を入れてあります(これより下では 5% の窓が 1 目盛りしかなく、小さい整数は必ず隣の数字の near-miss になる)。それでも外します。**この列が作られた理由の事例は、試験の中にはあり、現場にはまだありません。**`--drift 0` で列ごと切れます。

**2. 木ではなく、報告 1 本に当ててください。**このリポジトリの生成元である非公開の作業木は日本語の業務文書 480 ファイルで、**26,971 行**を返します —— 1 ファイル 56 行で、誰も読みません。`--min 100` にしても 20,618 にしかならない。原因は小さい数字ではなく、**議論のために書かれた文書は出典をリンクと参照で示し、その場に引き写さない**ことです。**報告 1 本なら 2 分で読めて、木に当てると壁になります。**これが正直な射程です。

**3. 同じファイルに引用があることは、その引用が本物である証明にはなりません。**数字を作れるモデルは、その上の引用も作れます。これが埋めるのは「**誰にも確かめようがない数字**」と「**確かめられる主張が添えられた数字**」の差 1 段で、全部ではありません。次の 1 段は人が URL を開くことで、だから `link-only` を黙って通さずに数えています。

## 1 行になる条件

1. ファイル内のどの引用にも入っていない、**地の文**にあること。
2. その値が**ファイル内のどの引用にも現れない**こと。表記は問いません: `1,200` は引用の `1200` で支えられ、`１，２００` も `1200` で支えられ、`30000` は引用の `3万` で支えられ、`8.6` には `8.6` が要ります。
3. **数字の形をした名前ではない**こと: 日付(`2026-09-16`・`2026年9月16日`・`9/30/2026`・`09-16`)・時刻・`v3.1`・semver・`§2`・`#3772`・`第3`・`[^12]`・コミットの hash・パス・URL・箇条書きの番号・`IMP-45` や `x20` のような識別子、そして単位が続かない `1900`〜`2100`(`1980 円` は値段、`1980` は年)。`--include-years` で年も数えます。
4. **主張と言える大きさ**であること: `--min`(既定 10)未満の裸の整数は数えるだけで並べません。単位が付いていれば —— `7%`・`¥7`・`7 件`・`7 days`・`7.5`・`1,200` —— 大きさに関わらず並べます。
5. **引用が 1 つも無いファイル**は既定で飛ばし、summary で数えます。引用の無いファイルについて「全部の数字が無根拠だ」は真ですが役に立たないからです。`--strict` で見に行きます。

**バッククォートで囲んだだけの数字は引用ではありません。**文中の `184` は書き手が自分の主張を強調しているだけで、`firings=184` はどこかから来た 1 行です。最初の版はこの区別を持っておらず、そして最初にやったことが表紙の洗濯でした —— 表の数字をバッククォートで書いた段落を足したら、その数字が全部「引用済み」になって件数が下がったのです。インラインコードは、**数字と記号以外の何かを含むときだけ**引用として数えます。

| フラグ | 何のため |
|---|---|
| `--min N` | 裸の整数の床(既定 10) |
| `--drift N` | near-miss の窓(%。既定 5。`0` で列ごと切る) |
| `--strict` | 引用が 1 つも無いファイルも見る |
| `--include-years` | 裸の 1900〜2100 を年ではなく数字として扱う |
| `--exclude GLOB` | パスを飛ばす(複数可。例 `--exclude 'MAP.md'`) |
| `--format tsv\|paste\|github` | 表 / パスも文字も出さない件数 / `::warning` 注釈 |

終了コード: **0** 無根拠なし・**1** あり・**2** 検査が成立しなかった。**1 ファイルも読めなかったときは 2 で終わります** —— 空の検査に緑の印を出すのは、エラーより悪いからです。

```yaml
- run: python unbacked-numbers/unbacked_numbers.py reports/ --format github
```

## しないこと

通信しません。標準ライブラリ以外に依存しません。人が文を書くファイル(`.md .markdown .txt .rst .adoc .org`)しか開かず、`.env`・`.pem`・`.key`・`id_rsa` の類は開きません。行を印字する前に、パスでも文章でもない「token の形をした 24 文字以上」を伏せます。`--format paste` はさらに進めて、**ファイル名も行の文字も数字も出しません**ので、そのまま公開の場に貼れます。

## 使わなくてよい人

報告がデータセットから生成されている、あるいは全ての数値が文献管理ソフトの引用に紐づいているなら、この道具に用はありません。**人かモデルが数字を文の中に打ち込み、下流の全員がそれを信じた**種類の文書のための物です。

## 試験

```bash
python -m unittest discover -s unbacked-numbers -p "test_*.py"   # 78 本
python unbacked-numbers/mutation_check.py                        # 22 通り、すべて捕捉
```

`mutation_check.py` は道具を 22 通りにわざと壊し —— `1,200` を `1` と読む・地の文が地の文を支えるようにする・日付を除く覆いを外す・`--format paste` に中身を出させる —— 試験がそれを通したら失敗で終わります。**最初の実行は 19 通り中 13 通りしか捕まえられませんでした。**残り 6 のうち 2 つは**道具の挙動が実際には変わらない駄目な変異**で、効く変異に差し替え、4 つは試験の穴でした(いまは `Backing`・`Splitting`・`Ignoring`・`CLI` にあります)。あとから足した 3 通りは、どれもこのリポジトリに当てて出てきた不具合 —— cp932 のコンソールで落ちること・伏せ字が普通の日本語を食っていたこと・下に書いたバッククォートの穴 —— から来ています。
