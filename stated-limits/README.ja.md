# stated-limits — 規約に書かれた上限は 44 個。数えられるのは 5 個だった

自走するエージェントを縛る規約ファイルに、公開の手順の節に、太字でこう書いてあった。

> **週 1〜3 回の push**

その規約が縛っているループは、作業の単位ごとに 1 つ公開する。1 日に 6 回 push していた。
誰も気づかなかった。**push を数えているものが何も無い**からだ。この文は計器の無い上限で、
守られている規則と同じファイルの、同じ書体の中に並んでいる。**誰も数えない上限は、弱い規則
ではない。そのファイルのどの行が飾りなのかを読み手に教える規則である。**しかも読み手は、全行
を手で確かめない限り、どれが飾りなのかを見分けられない。

`stated-limits` は文章を読み、その文書が自分に課した上限の数量を抜き出し、どのファイルの
ことを言っているのかを解き、測り、超えているものを名指しする。**解けなかった上限も、解けな
かった理由と一緒に印字する。**「上限が 44 個あって、測れる対象を指しているのは 5 個だった」
という事実そのものが結果であって、報告の穴ではないからだ。

```
$ python stated_limits.py CLAUDE.md --root . --all
documents      1
sentences      7
limits found   6
  checkable    4
  unverifiable 2
breached       2

CLAUDE.md:4  30 lines BREACH  [per-file]
  actual   47 lines  (over by 17 lines)
  measured rules  -- largest of 2 files: rules/web-safety.md
  said     Each file under `rules/` is 30 lines or under.

CLAUDE.md:5  200 characters BREACH  [per-line]
  actual   203 chars  (over by 3 chars)
  measured DECISIONS.md  -- longest line is line 1
  said     One line of DECISIONS.md is 200 characters or under.

CLAUDE.md:6  60 KB UNVERIFIABLE
  reason   no-target  (the sentence names no file to measure)
  said     Keep everything that loads automatically to no more than 60 KB.

CLAUDE.md:7  3 pushes UNVERIFIABLE
  reason   unmeasurable-unit  (a ceiling on events; no file can be counted to check it)
  said     1-3 pushes per week.
```

Python の標準ライブラリだけ。通信しない。読んだファイルを import も実行もしない。
終了コードは **0 = 超過なし / 1 = 超過あり / 2 = 検査そのものが走らなかった**。
**「確かめられない」は結果であって失敗ではない**ので、CI を赤くしない。

---

## 実測 —— これが出てきた 42 文書の木

| | 私的な規約の木 | この公開リポジトリ |
|---|---:|---:|
| 読んだ文書 | 42 | 35 |
| 文 | 6,566 | 4,924 |
| **書かれていた上限** | **44** | 11 |
| …**確かめられた** | **5** | 1 |
| …確かめられない | **39** | 10 |
| **破れていた** | **0** | **1**(ただし誤り。下に書く) |

(右の列はこのページ自身を含むので、このページを直すと動く)

確かめられなかった 39 の内訳。**21** は「3 回」「週 2 本」のような**回数の上限**で、どのファイル
を数えても確かめようがない。**12** は**どのファイルのことか文に書いていない**。**5** は名指しした
ファイルが**存在しない**。**1** は 3 つのファイルを挙げているが、**合計なのか各個なのかを書いて
いない**。

ここから読めることが 4 つある。

1. **その木の上限のうち、何かを指しているのは 11%。**11% が破れているのではない。11% だけが
   **問える**。残りは 1 ヶ月のあいだ読まれ、引用され、精神において守られてきたが、**一度も
   「測れるものについての主張」ではなかった**。
2. **破れ 0 は、見かけほど良い報せではない。**確かめられた 5 件が 5 件とも通っただけで、残り
   39 件はそもそも土俵に上がっていない。
3. **5 件のうち 2 件は上限にぴったり張り付いていた** —— 60 行の上限に対して 60 行、1 行 200 字
   の上限に対して最長行がちょうど 200 字。**そして 5 件のうち、その木の別の道具が実際に毎回
   数えているのは 1 件だけ**(リンク検査器が 200 字の規則を毎回測っている)で、**ちょうど 200 字
   だったのはその 1 件である**。計器があるところでは上限は最後の 1 単位まで使われ、計器が無い
   ところでは、そもそも文がファイルを名指ししていない。
4. **この道具が生まれた元の文には、上限を表す語が 1 つも無い。**「週 1〜3 回」はただの範囲で
   ある。だから**回数の単位に限って、範囲そのものを上限として読む**。測れる単位の範囲は読まない
   —— 「表の 3〜5 行目」がファイルへの判定になってはいけないからだ。

## 誤検出を、隠さずに書く

この道具をこのリポジトリ自身に向けると、1 件の「破れ」を報告する。**それは間違いである。**
ある README に「期日の手がかりが**40 文字以内**にあるときだけ報告する」という文がある。ここでの
40 文字は距離であって、ファイルの上限ではない。だがその直前の節がフォルダを名指ししていたので
対象が引き継がれ、この道具は「49,742 文字のフォルダが 40 文字の上限を超えている」と言った。

`--no-inherit` を付ければ消える。ただし同じフラグは、私的な木の**本物の上限 2 件**も
「確かめられない」に落とす。その 2 件が「第 1 層 = A.md / B.md。合計 250 行以内」という、
**ファイルは前の節に、上限は次の節に**という書き方だからだ。

**上限に見える文と、上限である文を見分けられるのは、それを書いた人だけである。**この道具は
推測し、どの推測をしたのかを報告に書く(`[target from the previous clause]`)。だから読み手は、
道具とではなく、その 1 行と議論できる。

## この道具に分からないこと

- **確かめられなかった上限が守られているかどうか。**39 件のうち 21 件は回数の話で、確かめるには
  ファイルではなくログが要る。別の計器の仕事である。
- **その上限が妥当かどうか。**書いてあるものを読むだけで、60 KB が適切な数字だったかについて
  意見を持たない。
- **KB。**50 KB は 50,000 バイトでもあり 51,200 バイトでもある(2.4% 違う)。実際のファイルは
  この 2 つの間に、思っているより頻繁に落ちる。既定では両方の読み方で判定し、**両方で超えて
  いれば `BREACH`、片方だけなら `BORDERLINE` として終了コードを変えない**。`--kb 1000` か
  `--kb 1024` で片方に固定できる。
- **知らない書き方の上限。**「以内」「以下」「まで」「or under」「no more than」等の語か、
  回数の範囲を手がかりにしている。「短く」「簡潔に」「1 ページ」は人には上限だが、ここでは
  見えない。
- **コードブロックの中の数字。**意図的に読み飛ばす(例の中の数字は規則ではない)。だから
  コードブロックの中にしか書かれていない上限は取り落とす。
- **ファイル以外の単位。**分・円・秒あたりのリクエスト数は集めていない。

## 使い方

```
python stated_limits.py [PATHS...] [--root .] [--glob '*.md'] [--exclude GLOB]
                        [--self] [--kb 1000|1024|both] [--no-inherit]
                        [--all] [--json] [--rewrite-hint]
```

- `--root` —— 文章の中の裸のパスを解決する基点。マークダウンのリンクは、マークダウンの読み手
  と同じく、その文書からの相対で解く。
- `--self` —— 「このファイル」「この文書」をその文書自身に解決する。**既定は切ってある。**
  推測だからで、終了コードを決める推測は、報告の穴より悪い。
- `--all` —— 通った上限も印字する。**一度はやったほうがいい** —— 上限にぴったり張り付いている
  行がいちばん面白く、既定では見えない。
- `--rewrite-hint` —— 確かめられない上限を数えられる形に書き換える例を 3 組印字する。

CI では、エージェントに「何をしてよいか」を教えているファイルに掛ける。

```yaml
- run: python stated_limits.py CLAUDE.md AGENTS.md .claude/rules/ --root .
```

出力は**構造として純 ASCII** で、引用した日本語は `<JP x12>` に畳まれる。これは気配りではない。
**隣の道具は、同じ木の中の検査器が全部の検査を終えたあと、cp932 の端末に緑の丸を印字して死に、
その上の門が終了コードを「失敗」と読んだから存在している。**上限についての報告が、ビルドを
壊すものであってはならない。

## テスト

```
python test_stated_limits.py     # 107 件
python mutation_check.py         # 24 通りにわざと壊し、全部捕まることを確認
```

`mutation_check.py` はこの道具の複製を 24 通りに壊す —— 比較を反転させる、合計の上限を最大の
ファイルと比べる、回数の上限を測れることにする、境界を破れと言う、改行まで変換して報告全体を
1 行にする —— そして**テストが見逃したものを報告する**。

**最初の実行は 24 のうち 23 を捕まえ、生き残った 1 つが 23 個ぶんの価値があった。**生き残った
壊し方は「glob を測る対象として扱う」で、それを捕まえるはずのテストは `` `test_*.py` `` を
渡していた —— **`/` を含まないので、`*` の検査がある分岐まで到達しない**。`` `docs/*.md` ``
で書き直したら、**壊していないほうの道具で落ちた**。パスの形をした glob が `docs/` を返して
いたので、**そのディレクトリの一部についての規則が、全部に対して検査されていた。**直したのは
先読み 1 か所。放っておけば、自信のある「破れ」として報告されていた。

破れを主張するテストには、必ず**同じ形で破れないことを主張する相方**を置いてある。これも効いた:
境界(`BORDERLINE`)の分岐は壊れた書式文字列のまま書き上がっており、境界のテストはどれも検査
までで止まって報告を組み立てていなかったので、**最初の本物の境界ファイルで落ちた**。報告まで
組み立てるテストは、いま在る。
