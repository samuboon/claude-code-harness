# quote-check — 引用は原稿にあり、出典も書かれていて、違うのは見えない 1 文字だけ

モデルが頁を読み、頁の言葉をそのまま鉤括弧に入れた原稿を書く。その言葉が本当に頁の言葉かは、
誰かが確かめなければならない。件数が増えるとその確認は `quote in source_text` になり、
返るのは「ある」か「ない」の 2 つだけになる。

**役に立たないのは「ない」のほうである。** 引用は、捏造されたから「ない」になることもあれば、
頁側が全角空白だったから「ない」になることもある。この 2 つは対処が正反対(主張ごと捨てる / 何もしない)
なのに、検査は両者を区別できない。だから「ない」が 1 件出るたびに、人が頁を読み直す時間が消える。

この道具は、まず**完全一致**で照合する。一致しなかった引用についてだけ、**書式の軸を 1 本ずつ緩めて**
—— 不可視文字・空白・引用符の形・ダッシュと三点リーダの形・文字幅・大小文字 —— どの軸が原因かを名指しする。
6 軸すべてを緩めても残る差は、文字そのものの差である。そちらは**最初に食い違った文字のコードポイント**を
付けて印字する。

```
$ python quote_check.py demo/report.md --sources demo/pages
quotes      9
exact       3
formatting  4
substantive 1
unfound     1

formatting difference (space)
  demo/report.md line 14
    quote   Fees are quoted exclusive of tax
    source  demo/pages/seller-terms.txt
    found   Fees are quoted exclusive of tax
    first difference at character 16: quote ' ' (U+0020 SPACE) vs source '\xa0' (U+00A0 NO-BREAK SPACE)
    identical once space is relaxed; the letters and digits are the same

substantive difference
  demo/report.md line 18
    quote   a platform fee of 7.5% of each sale
    source  demo/pages/seller-terms.txt, closest 97%
    found   a platform fee of 7.0% of each sale
    first difference at character 21: quote '5' (U+0035 DIGIT FIVE) vs source '0' (U+0030 DIGIT ZERO)

not found in any source
  demo/report.md line 20
    quote   the seller may withdraw funds at any time without notice
    no stretch of any source resembles it
```

効くのは下の 2 件である。上の 4 件は、「ある / ない」だけを返す検査がその 2 件を埋めてしまう雑音のほうだ。

標準ライブラリのみ。通信なし。終了コードは **0 = 全部が逐語**(書式の差は印字するが `--strict` が無ければ通す)、
**1 = 中身が違う引用があるか、どの出典にも無い**、**2 = 検査そのものが行われなかった**。

## 実測

**道具になった日(2026-09-11)。** 作業者が利用規約の頁から逐語の引用を 29 本持ち帰った。別のブラウザで
頁を開き直して 1 本ずつ突き合わせたところ、**28 本は一字一句一致し、1 本だけ食い違った。差は計算例の中の
全角空白 1 文字で、数字はすべて正しかった。** つまりこの照合の唯一の指摘は、**対処の要らない指摘**であり、
それを確かめるために人の読む時間を使った。問題の形はこれである —— **外れるものはほとんど書式の差なので、
「ない」としか言わない検査は、予算を全部まちがった引用に使う。**

このときの照合器は、ブラウザのコンソールに打ち込んだ 1 行の `innerText.includes()` で、もう残っていない。
測定器を捨てたのはこれで 5 回目として記録されている。**このファイルが、その照合器を残した形である。**

**この公開木の文章での抽出の実測。** 上位の `README.ja.md` からは、素の正規表現で **108** 件の引用符つきの
文字列が取れる。コードブロック・インラインコード・8 文字未満を外すと **61** 件になる(英語の `README.md` は
61 → 57)。コードは、何も引用していないのに引用符が並ぶ場所であり、そこを読む検査は誰も手を打てない指摘を出す。

**テスト 42 本。変異 25 件、全件が捕まる**(`python mutation_check.py`)。

**最初の変異検査は書き残す価値がある。** 22 件中 19 件が捕まり 3 件が生き残ったが、**うち 2 件は「書き換える
対象の文字列がファイルに無かった」ために生き残った。** ソースが、escape 表記のつもりで**実体の不可視文字**で
書かれていたのである —— 道具側に 65 文字、テスト側に 56 文字の非 ASCII 文字があり、その中には文字列リテラルの
中に座った zero-width space と no-break space が含まれていた。**不可視文字を見つける道具が、自分のソースに
不可視文字を抱えていた。**気づいたのはテスト(緑だった)ではなく、**対象を見つけられなかった変異**のほうだった。
**いま 2 つのファイルは意図して ASCII のみである** —— この道具が扱う文字は、すべて `\uXXXX` の形でそこに見える。

## 使い方

```bash
# 原稿 1 本と、保存した出典の頁を入れた フォルダ
python quote_check.py report.md --sources pages/

# 出典を名指しし、書式の差でも落とす
python quote_check.py report.md --source pages/terms.txt --source pages/fees.txt --strict

# markdown の引用ブロックも引用として数える
python quote_check.py report.md --sources pages/ --blockquote --json
```

| 指定 | |
|---|---|
| `--source FILE` | 出典のファイル(繰り返し可) |
| `--sources DIR` | フォルダ以下の読めるテキストすべて |
| `--min-length N` | 検査する最短の長さ(既定 8 文字) |
| `--blockquote` | markdown の `>` の連続を 1 つの引用として扱う |
| `--strict` | 書式だけの差でも落とす |
| `--json` | 引用 1 件 1 レコード(パイプライン用) |

引用は `「...」` `『...』` `“...”` `"..."` から取る(コードブロックとインラインコードの外だけ)。
ファイルは UTF-8 で読み、読み込み時に NFC へ正規化する。**Unicode の合成の違いだけで食い違う引用は同じ引用**
として扱う —— 両側に、比較の前に、1 回だけ当てる。

**出典は URL ではなく、自分が保存したファイルである。**これは意図的で、頁を自分で取りに行く検査は、
「今日の頁」と「別の日に取った引用」を突き合わせることになり、**頁が変わっただけの引用を捏造として報告する**。
読んだものを保存し、保存したものに対して照合する。

### CI で

`example-workflow.yml` は push ごとに走り、**中身の差だけ**で落ちる。

## できないこと

- **意味を読まない。**逐語であっても、意味が反転する切り方をした引用は通る。逐語で、正しく、無関係な引用も通る。
- **どの出典が正しいかは知らない。**一致したファイル名は出すが、原稿が別の出典を挙げていることは検出できない。
- **引用符の外の主張は見えない。**言い換えは検査の対象にならない。だから正しい使い方は上流にある —— 引用してから照合する。
- **`unfound` は捏造の証明ではない。**渡したファイルのどこにも似た箇所が無かった、という意味でしかない。
  多くの場合、原因は**その出典を保存していないこと**である。
- **正規化は 1 文字ずつ**なので、読み込み時の NFC を越える合成は畳まれない。珍しい分解を含む引用は中身の差として出る。
- 軸は固定で 6 本、順序は `invisible, space, quotes, punct, width, case`。最初に一致させた軸が報告される。

## この道具の出どころ

12 ヶ月で利益 1,000 万円を作ることを目標にした事業を AI が回しており、その仕事の大半は、他人の規約を読んで
書かれていることを書き留めることである。手数料・入金までの日数・解約の通知期間 —— **その原稿の数字はどれも
荷重を負っており**、どれも「誰かが信じるしかない引用」として届く。

**防いでいるのは、モデルが引用を捏造することではない。**モデルが引用を 99% 正しく写し、検査が「無い」と言い、
**この事業で唯一足りない資源である人間**が、10 分かけて「消えていたのは空白 1 文字だった」と突き止めることである。
