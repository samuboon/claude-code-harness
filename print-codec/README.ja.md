# print-codec —— 検査は全部通った。止めたのは最後に出した緑の丸だった

2026-09-16 の朝、無人のループの中でリンク検査が仕事を終えました。壊れは 0 本。
そのあと要約の行を印字しようとして、そこで死にました。

```
UnicodeEncodeError: 'cp932' codec can't encode character '\U0001f7e2' in position 106
```

終了コード 1。上にいる門は終了コードを読むので、記録に残ったのは**検査が失敗した**。
そして `1` という数字の中には、**「リンクが 7 本壊れている」と「報告係が自分の句読点で倒れた」を
見分けるものが何もありません。**木は綺麗でした。その回は失敗として数えられました。

`print-codec` は Python のソースを**実行せずに**読み、標準出力・標準エラーに届く文字列リテラルを集め、
指定したコンソールのコーデックが拒む文字を名指しします。**自分で出力の符号化を固定しているファイルは
「保護済み」**として、危険の数から外します。

```
$ python print_codec.py tools/ --codec cp932
codec          cp932
files read     63
protected      20
at risk        2 file(s)
lines          4
characters     2 distinct

tools/linkcheck.py  (decides an exit status)
  line 161   print
    print("検査した相対リンク {} 本 / 壊れ {} 本 / ... / ISSUES の <U+1F7E2> {} 行"
    U+1F7E2 LARGE GREEN CIRCLE
```

標準ライブラリのみ。通信なし。読んだファイルを import しません。
終了コードは **0 = 危険なし / 1 = ある / 2 = 検査そのものが走らなかった**。

## 実測 —— この道具が出てきた非公開の木(63 ファイル)

| `--codec` | 読んだ | 保護済み | 危険 | 行 | 文字の種類 |
|---|---:|---:|---:|---:|---:|
| `cp932`(日本語 Windows のコンソール) | 63 | 20 | **2** | **4** | 2 |
| `utf-8` | 63 | 20 | 0 | 0 | 0 |
| `ascii` | 63 | 20 | **20** | **110** | 310 |

ここから読み取れることが 4 つあります。

1. **名指しした 4 行のうち 2 行が、その朝ループを実際に止めた行です。**予告で終わらせずに走らせて
   確かめました —— コンソールを cp932 に固定すると、道具が指したファイルの、道具が指した行で、
   このページの冒頭の逐語のまま落ちます。**`position 106` まで一致します。**
2. **残りの 2 行は、まだ誰も踏んでいない同じ地雷です。**`harness_size.py` が `U+2717 BALLOT X` を
   2 回印字していて、しかもこれは**終了コードを決めるファイル**です。日本語のコンソールで初めて
   走った朝に、門に対して同じ嘘をつきます。
3. **面白いのは対照の行のほうです。**2 日前の 2026-09-14 に、同じ木の別のファイルが同じ理由(全角ダッシュ)で
   落ちていて、そのときは**その 1 本だけ直しました**。そのファイルは今回 `protected` で 0 件。
   **1 つの木の中に、直った側と開いたままの側があった** —— 誰ももう一方を探しに行かなかったからです。
4. **`ascii` の行は、この道具の限界の実演です。**コーデックを間違えて渡すと木が丸ごと赤くなります
   (63 ファイルの日本語の文字列が全部当たる)。**この道具はあなたのコンソールが何かを知りません。**
   `--codec` を渡すのはあなたで、間違えれば自信に満ちた無用な 110 行が返ります。

## 報告そのものが、自分の規則を生き延びないといけない

コンソールが印字できない文字についての報告が、その文字を印字してはいけません。問題の行をそのまま
引用して見せるのは、**まさにこの道具が、自分の報告するバグで死ぬやり方**です。だから引用する行も
パスも一度置き換えを通し、文字があった所には `<U+1F7E2>` が出ます。

他と同じやり方で確かめました —— コンソールを cp932 に固定して同じ木に当てると、報告 27 行を出し切って
終了コード 1 で終わります。**苦情を言っている当の 4 文字は、一度もストリームに届きません。**

## この道具に言えないこと

- **実行時に組み立てられるもの。**f-string の穴・変数の中身・引数。読むのはリテラルの側だけです。
  モジュール直下の `NAME = "..."` は 1 段だけ追い、**2 回代入された名前は推測せずに捨てます。**
- **`logging` の出力がコンソールに届くかどうか。**ハンドラ次第なので既定では読みません。
  `--include-logging` で入りますが、偽陽性ごと受け取ることになります。
- **「保護済み」が「読める」を意味するかどうか。**保護は文字列の一致で見ています
  (`reconfigure(...)` / `TextIOWrapper(sys.stdout.buffer...)` / `PYTHONIOENCODING`)。
  cp932 のコンソールで UTF-8 に固定すれば**例外は出なくなりますが、その文字が読めるようにはなりません。**
  文字化けした要約と引き換えに、偽の失敗を消す —— それがここで欲しい取引です。
- **あなたのコンソールの実際のコードページ。**Windows Terminal・`cmd.exe`・CI・パイプで、1 台の中でも
  4 通りの答えがあります。
- **Python 以外。**シェル・Node・Go でも同じことは起きますが、この道具の担当ではありません。

## 使い方

```
python print_codec.py [PATHS...] [--codec cp932] [--all] [--json]
                      [--include-logging] [--exclude GLOB] [--fix-hint]
```

- `--codec` —— Python がコーデックを持っているものなら何でも。既定は `cp932`。UTF-8 でないロケールでも
  出力を通したいなら `ascii` が一番厳しい実用設定です。
- `--exclude` —— 繰り返せるグロブ。ファイル名と posix のパスの両方に当てます。よく使うのは
  `--exclude "test_*.py"`(試験ファイルはわざと壊れた文字列を持っているため)。
- `--fix-hint` —— この種類の問題を丸ごと終わらせる 3 行を印字します:

```python
import sys
for _s in (sys.stdout, sys.stderr):
    try:
        _s.reconfigure(encoding="utf-8", errors="backslashreplace")
    except AttributeError:  # Python 3.7 より前
        pass
```

CI では、**終了コードを他人が信じているスクリプト**に当てるのが効きます:

```yaml
- run: python print_codec.py tools/ --codec cp932 --exclude "test_*.py"
```

## 試験

```
python test_print_codec.py        # 106 本
python mutation_check.py          # わざと壊した 24 通り、すべて捕捉
```

`mutation_check.py` は道具の写しを 24 通りに壊します —— 印字できない文字を「印字できる」と答える /
報告が問題の行をそのまま引用する / `--exclude` を無視する / 保護済みのファイルでも終了コードを 1 にする ——
そして試験が見逃したものを名指しします。**最初の実行は 24 通り中 23 通りしか捕まえられませんでした。**
生き残ったのは「見つけた順に返す(並べ替えをやめる)」で、`ast.walk` が単純なファイルではたまたま行順に
近いため、それまでの試験が気づきませんでした。いま捕まえている試験は、**関数の中の `print` を、
モジュール直下の `print` より前の行に置きます**(歩き方が逆順で返す形)。
