# tile-seam —— 継ぎ目の無い自分たちのテクスチャ 44 枚のうち 27 枚が、誰もが書く継ぎ目検査に落ちた

テクスチャが「継ぎ目が無い」とは、右端が左端に続いているということです。これを確かめる素直なやり方は、
**その境目の段差を測って閾値と比べる**ことでしょう。

**その検査は間違っていて、それを知っているのは自分たちが一度出したからです。**2026-09-13、布地テクスチャの
生成器にまさにその検査を書き、**周期性が証明できている柄まで「継ぎ目あり」と断じました。**織りの畝は、
隣り合うふつうの列と列の間でも、境目と同じだけ段差を作るからです。あの検査には、どちらの端かを見分ける
手段がありませんでした。

`tile_seam.py` が聞くのは別の問いです。

> **その境目は、この絵の中でいちばん悪い端か?**

画像の中の隣り合う列の組が、それぞれ 1 つの数を出します。境目も 1 つ出します。**境目がそのすべてを上回った
なら、それは継ぎ目です。**分布の中に収まっているなら、その柄はどこでも同じくらい荒いというだけで、何も
壊れていません。

```bash
python tile_seam.py path/to/textures            # 0 = 何も無し、1 = 継ぎ目あり
python tile_seam.py pack/ --tsv                 # 1 ファイル 1 軸につき 1 行
python tile_seam.py pack/ --naive               # …と、固定の閾値なら何と言ったか
```

標準ライブラリのみ。Unity 不要・PIL 不要・インストール不要。

## 答えが先に分かっているテクスチャで測った

**2026-09-13 に BOOTH で無料配布した布地テクスチャ 44 枚。**これらは周期が厳密に一致する数式から作られて
おり、**生成器自身の検査が「周期のずれの最大 0.000000」と出します。**それが証明しているのは**数式**の周期性
であって、出てきた PNG の周期性ではありません。だからこの 44 枚は、この道具を当てる相手として公平です。

| | 結果 |
|---|---|
| **tile-seam** | **継ぎ目 0 枚・疑い 1 枚・問題なし 43 枚** |
| **境目の段差だけを 8/255 の固定閾値で見る** | **44 枚中 28 枚が「継ぎ目あり」** |
| **…そのうち tile-seam が問題なしと言う枚数** | **27 枚** —— つまり**自分たちの品揃えの 61%** が、素直な検査で殺される |
| 時間 | 512×512 が 44 枚で **4.3 秒**(120 枚で 16.5 秒。1 枚おおよそ 0.1 秒) |

**唯一きれいでない 1 枚も自分たちのものです。**`Gingham_Navy_color.png` が両軸とも `suspect`(疑い)に
なります。境目が自分自身の隣接段差の 99% を上回り、最悪までは届いていません。**これは誤検出です** ——
柄は厳密に周期的です。**これが `suspect` という帯の代金**であり、だからこそ `suspect` は `seam` とは
別の語で、終了コードを変えません。

**対照も置きました。正直なほうの対照です。**タイル用に作られていないマットキャップの球 120 枚に当てると、
**継ぎ目 74 枚・問題なし 46 枚**と出ます。46 枚は見落としではありません。背景が四辺すべてに届いているので、
**その 46 枚の境目の段差は最大でも 255 分の 0.1992**、92 本の軸のうち 64 本は**ちょうど 0** です。あの
画像は本当にタイルとして並びます。同時にこれは、この測定が何**でない**かを示しています ——
**端が静かな絵は、真ん中に何が描いてあっても通ります。**

## 出力の読み方

```
file                          size       left/right wrap           top/bottom wrap
Stripe_Mono_color.png         512x512    ok      x134.00  97% r    ok      x0.00     0% r
Quilt_normal.png              512x512    ok      x7.48    97% r    ok      x7.48    97% g
Gingham_Navy_color.png        512x512    suspect x64.50   99% r    suspect x64.50   99% r
```

- **`x134.00`** —— 境目の段差を**中央値**の隣接段差で割った倍率。読みやすいですが、**意図して判定には
  使っていません。**`Stripe` は中央値の 134 倍でありながら問題なしです。縞の布地は列の段差の中央値が
  ほぼ 0 で、縞の縁だけが巨大だからです。
- **`97%`** —— **その画像自身の隣接段差のうち、境目が上回った割合。判定するのはこの数です。**100% なら
  境目がこの絵でいちばん悪い端 = `seam`。100% に届かず 99% 以上なら `suspect`。それ未満は `ok`。
- **`r`** —— いちばん悪い答えを出したチャンネル。R/G/B/アルファを**別々に**測るので、**アルファだけ・
  青だけにある継ぎ目**も見つかります。
- `--strict` は `suspect` の線を 99 パーセンタイルから 90 パーセンタイルに下げます。すぐ下に何が
  いるかを見るためのものです。

## できないこと

- **PNG だけ**、かつインタレースなし。16 ビットは上位バイトだけを読みます。JPEG・TGA・PSD は
  推測せずに理由を書いて飛ばします。
- **画像の中に既にある端より悪くない継ぎ目は、見つけられません。**これは設計そのものであり、同時に
  壊れ方でもあります —— テクスチャの周りに硬い枠を 1 本引けば、いちばん悪い端は境目ではなく枠になります。
- **境目の段差は、その辺全体の平均です。**狭い帯にだけ出ている継ぎ目は、両側の行に薄められます。
- **鏡写しのテクスチャは通ります。**鏡写しのテクスチャは本当に継ぎ目が無いからです。ただし**鏡写しで
  あることは教えません。**
- タイルとして**見栄えがよいか**、遠景で繰り返しが見えるか、見つけたものをどう直すかについては、
  何も言いません。

## 試験

**試験 68 本・わざと壊した 21 通り・21 通りとも捕捉。**ただし `mutation_check.py` の**初回は 20 通り
までしか捕まえられず**、その中身は両方とも書き留める価値があります。

1. 生き残ったのは Paeth 予測子の同点処理を壊すもの(`pa <= pb` → `pa < pb`)でした。生き残った理由は
   **これが等価な変異だったから**です。算術を追うと、この 2 つの形は違うバイトを出せません。出せる
   変異に差し替えました。
2. それを確かめる過程で、**試験側の PNG 書き出しが、道具自身の `_paeth` を呼んでいた**ことが分かりました。
   予測子を壊すと書き出しも同じように壊れ、往復は通ってしまいます —— **あの試験は落ちようがなかった**の
   です。いまは RFC 2083 §6.6 から書き起こした 2 本目の予測子を試験側が持っています。

```bash
python -m unittest test_tile_seam -v
python mutation_check.py
```

## 買ったパックに当てたら

**面白いのは、これが間違っている場合です** —— ちゃんとタイルになるのに `seam` と出たもの、逆に継ぎ目が
見えているのに `ok` と出たもの。そのための
[Issue の雛形](https://github.com/samuboon/claude-code-harness/issues/new?template=seam-verdict.yml)
があります。`--tsv` の行を貼ってください。数字とファイル名だけで、画像そのものは含みません。

**この道具を当てた 164 枚は、全部こちらが作ったものです。**上のどの数字よりも、そこがいちばん弱いところです。
