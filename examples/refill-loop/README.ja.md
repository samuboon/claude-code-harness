# refill-loop —— 自走ループが朝、1 単位も回さなかった日と、どちらが正しいか決められない 2 つの直し方

自走する AI のループには、丸 1 日を潰すのにどのログにも残らない失敗が 1 つあります。
**待ち行列に「今日取れる行」が無くなり、AI が止まる**というものです。落ちてもいないし、
拒否もされていない。やることが無いと言って、12 時間戻らない人間を待っていただけです。

ここに置いたのは、その 2 つの答えの最小実装です。**両方**入れてあります。どちらが正しいか、
私たちにも分かっていないからです。Python 標準ライブラリだけ・依存なし・合計 300 行ほど。

| ファイル | 側 | やること |
|---|---|---|
| [`queue_forecast.py`](queue_forecast.py) | **A —— 前夜に検知する** | 23 時に走らせる。翌朝に取れる行が何本あるかを数え、0 本なら声を上げて落ちる。**人がまだ起きていて、直すのに 1 行で済む時刻に。** |
| [`refill_loop.py`](refill_loop.py) | **B —— その場で補充して走り続ける** | ループの中で走らせる。取れる行が無いとき「停止」を返さず、**補充の単位**を返す。中身は「上流に戻って自分で 3 行開け」という 1 単位の仕事。 |

## 実際にいくら失ったか(実測・2026-09-15・1 件)

私たちの本線は、行列の 1 行を文脈ゼロの作業者に渡し、作業者は commit で終える形で回ります。
前の晩、作業者が行列を整えたときに**全部の行に日付を付けました**。新しい行を生むのが仕事で、
だからこそ日付を付けてはいけない最後の 1 行にまで。

| 前夜 22:09 の行列 | |
|---|---:|
| 未了の行 | **9 本** |
| うち人待ち | 1 本 |
| うち 09-16 以降に送られた行 | **8 本**(最後の行を含む。09-21 が付いていた) |
| **翌朝に取れる行** | **0 本** |

| 翌朝 08:39 → 10:29 | |
|---|---:|
| commit が出た時間 | **53 分**(3 単位・3 commit) |
| 何も出なかった時間 | **57 分** |
| …行列が空で、人が気づくまで止まっていた | 12 分・**commit 0** |
| …後の単位が承認の線に当たり、commit せずに終えた | 27 分・**commit 0** |
| …本線が同じ行をもう 2 回出し直した | 40 秒・**commit 0** |

同じ 2 時間の中に、何も生まない道が 2 通りありました。ここで扱うのは 12 分のほうです
(27 分のほうは「承認が要る = ターンを終えてよい」と解釈する別の欠陥で、このリポジトリの
別の場所で直してあります)。

ここで使われている人間の予算は **1 日 10〜20 分**です。08:39 に止まって 08:39 に気づかれる
ループはほとんど何も失いませんが、08:39 に止まって 21 時に気づかれるループはその日を失います。

## 走らせ方

```console
$ python queue_forecast.py sample_QUEUE_broken.md --date 2026-09-15
2026-09-15  open 9 / actionable 0  (blocked 1, postponed 8, next 2026-09-16)
  F1  0 of 9 open rows are actionable on 2026-09-15 ...
  F2  the last open row (line 20) carries a date (2026-09-21) ...
$ echo $?
1

$ python refill_loop.py sample_QUEUE_broken.md --today 2026-09-15
action : unit  (refill)
kind   : upstream
why    : 0 of 9 open rows are actionable (1 blocked on a human, 8 postponed; next one frees up 2026-09-16)

$ python test_refill_loop.py
Ran 19 tests in 0.003s
OK
```

`sample_QUEUE_broken.md` は、実際に壊れた行列の**印と日付だけ**を commit から取って並べた
ものです。行の本文は差し替えてあります(印・日付・本数は実物)。

**行列の書式** —— markdown のチェックリスト 1 行 = 1 単位:

```markdown
- [ ] 〔定型 09-16〕 棚 A | D+3 の数字
- [ ] 〔判断〕 (待) 棚 B | 人待ち
- [ ] 〔判断〕 生成型 | 新しい行を生む発注を書く
```

`定型`(機械で済む)/ `判断`(誰かが決める必要がある)/ `上流`(計画そのものが問われている)——
この印で安いモデルと高いモデルを振り分けます。日付は「その日まで取らない」。`(待)` は人待ちで、
ループは飛ばします。英語の印(`(routine 09-16)` `(wait)`)も同じように読めます。

## 私たちが割れているところ

同じ問いを 2 人の検査役に出したら、答えが割れました。どちらも馬鹿げていません。

> **A.** 行列が空になるのは**計画の失敗**であり、計画の失敗は決まった時刻に、安く、人間が
> 捕まえるべきだ。前夜に検知して知らせればいい。08:39 に自分で行列を補充する AI は、
> 読む人が誰も起きていない時間に自分で発注書を書いている AI だ。

> **B.** 人が起きていることに依存する検査は、その時点で負けている。ループの仕事は走り続ける
> ことで、「行が無い」は異常ではなく**上流そのもの**だ。仕事として AI に返すべきだ。前夜に
> 検知するのは、止まる時刻を前夜に移しただけだ。

両方作りました。確かなのは 2 つに共通する 1 点だけです ——
**行列が空であることを、ターンを終える理由にしてはいけない。**

**自走ループを回している方へ: あなたはどちらを使っていますか。もう一方で痛い目を見ましたか。**
[Issue](https://github.com/samuboon/claude-code-harness/issues) に書いてください。
両方を 1 つのリポジトリに入れた理由はそれです。

## 言えないこと

- **n = 1。**1 件・1 つの朝・1 つのプロジェクト。上の数字は全部実測ですが、どれも「率」ではありません
- **補充の経路は本番で 0 回しか発火していません。**事故の朝に足したもので、以後、行列が空に
  なっていないためです。根拠は試験だけです
- **予告検査は本番で一度も走っていません。**ここが初めての実装で、壊れた実物に**後から**
  当てて確かめただけです —— 証拠としては最も弱い種類のものです
- **どちらが優れているかは示せていません。**「補充が良い行を開いた」と「補充が仕事を捏造した」
  を切り分ける計器が無く、後者は B 側の分かりやすい失敗です
- 日付の比較は本番の写しより少しだけ厳しくしてあります。`MM-DD` を文字列で比べず、最も近い年に
  解決します(本番の写しは毎年 1 月に間違えます)。その欠陥を見つけた試験(`02-29`)も入れてあります
