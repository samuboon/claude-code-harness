# moved-path-check —— replicate/cog の AGENTS.md は、2 月に消えたファイルへ今もコーディングエージェントを案内している

`replicate/cog` の `AGENTS.md` は「コーディングエージェントへの案内」で、その「Important Files」の節に
`python/cog/base_predictor.py`(「Predictor interface」)が載っています。このファイルは 2026-02-04 のコミット `df576ff` で削除されました。
`AGENTS.md` はその後 2026-04-24 にも手が入っていますが、一覧は古いままです。コードレビュー用のスキル
(`.opencode/skills/cog-review/SKILL.md`)にも「`python/cog/base_predictor.py` を変えると下流のモデル作者すべてに響く」とあります。
`GetBindu/Bindu` では、エージェント向けに書かれた手順書 `.agents/workflows/testing.md` が
`uv run pytest tests/unit/test_applications.py` ほか 4 本のテストをパスで名指しして走らせます。5 本とも 2026-03-19 に `tests/unit/` から出ました。
4 本は 1 日のうちにサブフォルダへ戻り(`test_applications.py` は今 `tests/unit/server/test_applications.py`)、`test_did_extension.py` はもうありません。

これが起きても、どこも失敗しません。バッククォートの中やシェルの枠の中のパスはリンクではないので、リンク検査は読みません。
文書の中から「今は無いパス」を grep すれば何百件も出ます —— 例として書いたパス、読者自身のプロジェクト、ビルドの出力先 ——
だから誰もやりません。**見分けはリポジトリの履歴が付けます。**一度もここに無かったパスは、よそのパスです。
あるコミットが消すまでここにあったパスは、古くなった一文です。

`moved_path_check.py` は文書を読み、出てくるパスを 1 つずつ `git log` で引いて、後者だけを出します。
消したコミットと日付、git が分かるときは今の場所を添えます。

```bash

python moved_path_check.py docs/ README.md  # これだけ
python moved_path_check.py --since v2.0     # v2.0 より後に動いた・消えたものだけ
python moved_path_check.py --json
```

## 何を出すか

| コード | 重さ | 意味 |
|---|---|---|
| `MOVED` | error | パスは改名された。git の履歴によれば今はここにある。相対リンクなら、その文書から見た相対パスで出すので、そのまま貼れる |
| `MOVED_DIR` | error | フォルダが改名された。中のファイルの半分以上が、示したフォルダへ移った |
| `DELETED` | error | 示したコミットで削除され、git は改名と見ていない。同じ名前のファイルが今ちょうど 1 本あれば、手がかりとして名前を添える |
| `DELETED_DIR` | error | フォルダの中のファイルがすべて削除された(最後の 1 本を消したコミットを示す) |
| `HISTORICAL` | warning | 上のどれかだが、文そのものが renamed・removed・formerly・deprecated などと言っている。変更を説明している文だろう |
| `SHORTENED` | warning | 新しいパスが古いパスで終わる(`packages/core/x.ts` → `plugin/packages/core/x.ts`)。そのフォルダの中から見た書き方かもしれない |
| `ELSEWHERE` | warning | ここでは削除されたが、パスの末尾が同じファイルが別の場所にある |
| `SPLIT_DIR` | warning | フォルダの中身がいくつもの場所へ散った |

**何を読むか。**相対リンクと画像(`[x](../src/a.py)`・`[id]: path`・`src="…"`)、GitHub 上のこのリポジトリへのリンクのうち
今チェックアウトしているブランチを指すもの(`github.com/OWNER/REPO/blob/main/…`。別のブランチ・タグ・コミットへのリンクは触らない ——
`vuejs/vue` の `tree/dev/…` は、2022 年から誰も触っていない dev ブランチの上で今も生きている)、スラッシュを含むパスに見えるインラインコード
(`src/a.py`・`docs/`)、`sh`・`bash`・`console`・`powershell` の枠の中のスラッシュを含む語(コマンドだけ。`console` はプロンプトのある行だけ、
コメントは読まない)、rst と AsciiDoc の `include`・`image`・インラインリテラル。バッククォートの中のパスは、その文書のフォルダ、
その上のフォルダ、…、ルートの順に当てます。

**わざと読まないもの。**
- 履歴に**一度も無かった**パス。よそのパスです(読者のアプリ、例、別のリポジトリ)。一度も無かったファイルへの相対リンクは綴り違いで、
  それはリンク検査が既に拾います
- **今 `.gitignore` に入っている**パス。手元のファイルか生成物になったものです(`dist/`、隣に置く別リポジトリのクローン)。
  使うのはリポジトリの `.gitignore` だけで、検査する人のグローバルな除外設定は使いません
- バッククォートの中の**裸の名前**(`.env`・`requirements.txt`・`index.js`)。最初の測定で、ほとんどが読者のファイルでした。リンクなら裸の名前も読みます
- 今このリポジトリに無い `.claude/…`・`.cursor/…` などのドットフォルダ。読者の設定です
- **記録。**変更履歴、リリースノート、移行ガイド、ブログ記事、RFC、ADR、版ごとの文書、作業の記録(`plans/`・`work-items/`・`slices/`・`evidence.md`)、
  パスに日付の入った文書(`2026-03-14-phase1.md`)、`old_files/`・`README_OLD.md`、冒頭で「superseded」と言っている文書。
  その日のパスを書き残すのが役目だからです。`--all-docs` で読ませることもできます
- ほかの言語のコードの枠、出力、ツリー。そのパスが何を基準にしているかを検査は知りようがありません
- 取り込まれる断片(`macros/`・`_includes/`・`partials/`・`snippets/`)の中のリンク。取り込む側のページから解決されます

**どこへ行ったかをどう知るか。**`git log --raw --no-renames` はファイルの中身を 1 つも読まずにすべての削除と追加を返すので、
`--filter=blob:none` のクローンでも動きます。コミットごとに、削除を追加と組にします —— 同じ blob、無ければ同じファイル名、
無ければ拡張子だけ違う同じ名前(`ask.test.ts` → `ask.test.js`)、無ければ同じフォルダに 1 本だけ足された同じ種類のファイル。
組にならなかった削除は、「削除」と言う前に git 自身の中身による改名の検出(`git show -M40%`)に聞きます。
改名の連鎖(`a` → `b` → `c`)はたどり、一度戻ってまた消えたパスは、いちばん新しい消え方で判定します。

## しないこと

- **シンボリックリンクはたどらない。**git がシンボリックリンク(mode 120000)として持つリンクを通るパスは、無いと出ます。最終の測定で唯一の事実の誤りです
- **文中で名指ししたフォルダを基準にしたパス**(「アプリの `src/`」の意味の `src/`)は、文書のフォルダ・その上・ルートからしか解きません。
  モノレポのテンプレートでは、これが残った誤報のいちばん大きな出どころです
- **削除されたフォルダと同じ名前の Go や Python のパッケージ名**(`database/sql`)は、パスと見分けられません
- **`pytest パス::ノード`** の形や、知らない記号にくっついたパスは読みません(Bindu の 54・57 行目の
  `tests/unit/test_applications.py::TestBinduApplication` は取りこぼします)
- **バッククォートの中のコマンド全体**(`` `python scripts/install.py --prepare` ``)は読まず、バッククォートの中にパスだけがあるときに読みます。
  バッククォートの無い地の文のパスも読みません
- **言語名の無いコードの枠、プログラミング言語のコードの枠、出力は読みません。**Python の例の中の古い `import` のパスは見つからず、
  `tweakcc-gilligan` の言語名の無い ``` の枠のコマンドも見つかりません
- **`--rev`** ではチェックアウトせずにコミットを読むので、`.gitignore` は見ません
- **浅いクローン**では、検査の拠り所である履歴が見えません。そう言って、無いリンクを引けないときは 2 で終わります。GitHub Actions では `fetch-depth: 0` にしてください

**同じところを見ているもの。**リンク検査(`lychee`・`markdown-link-check`)は相対リンクが解決するかを見ますが、ファイルがどこへ行ったかは見ず、
バッククォートやコマンドの中のパスも読みません。[kontext](https://github.com/patkusch/kontext) は git の履歴から文書が古いことを示し、
移ったフォルダも追いますが、対象は文書が前付けの `describes:` で宣言したコードのパスで、本文に書かれたパスは読みません。
本文のパスを読んで git にどこへ行ったかを聞くものは、私たちは見つけられませんでした。あれば教えてください。

## 試験

`python test_moved_path_check.py` —— 60 件。ほとんどは一時フォルダに小さな git リポジトリを作って当て、終わったら消します。
`python mutation_check.py` は検査を 43 通りに 1 つずつ壊し、試験が気づかなければ失敗します。**43 通りすべて捕まり、初回は 42 通り中 36 通りでした。**
通り抜けた 6 通りのうち 1 つは中身が同じことによる改名の組で、git 自身の改名の検出も同じものを見つけるため、どの試験でも見分けられませんでした(今は git を使わずに組み方だけを試験しています)。
4 つは、試験の例が別の規則でも弾かれていた規則です(`plans/` の中の日付入りの計画、もともと地の文だった `.txt`、行末で終わる HTML コメント、
動いたファイルに届かない断片のリンク)。残る 1 つは壊し方そのものの誤りで、何も変えていませんでした。

このリポジトリに当てると、文書 67 本で error 0 件・warning 0 件です。
