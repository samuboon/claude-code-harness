## 検索窓では届かない、たった 1 つのこと

**GitHub は 👍 で並べ替えも絞り込みもできません。** 検索の `reactions:` 修飾子も画面に出る数も
`reactions.total_count`、つまり 👍 😄 🎉 😕 ❤️ 🚀 👀 👎 を全部足した数です。だから素直に検索して
得られる順位は「需要の順位」ではなく「注目の順位」で、両者は肝心なところで食い違います。

| Issue | 👍（`+1`） | `total_count` | 👍 順 | 合計順 |
|---|--:|--:|--:|--:|
| `microsoft/TypeScript#13219` | **1,430** | 1,903 | **1 位** | 2 位 |
| `rust-lang/rust#100000`（ネタ Issue） | 1,046 | **3,011** | 3 位 | **1 位** |

この道具は `reactions["+1"]` だけを読みます。この 1 行が道具の存在理由なので、守りを 3 枚
重ねました —— `self-check` 命令、6 本の単体試験、そして**必ず試験を落とさなければならない
変異（M1）**です。

**今日の実測**: `reactions:>=100` で GitHub が返した 121 件のうち、**13 件は 👍 が 100 に
届いていません**。議論（😕・👎）が多かっただけで一覧に入っていた行です。この道具はそれを
落とし、落とした件数を出力の冒頭に書きます。

## 試験が効いていると言える理由

落ちるところを一度も見ていない試験は飾りです。`mutation_check.py` は道具を 17 通りに
書き換え（`total_count` を数える／昇順に並べる／Issue 番号だけで重複除去する／本文を残す／
`|` の escape をやめる／改ページを止めない…）、素通りした変異を報告します。**17 種すべて
捕捉**。元のファイルは `finally` で必ず戻します。

最初に走らせたときは **12 種中 11 種**でした。生き残ったのは「改行を空白に置換するのをやめる」で、
理由は次の行がすでに空白を畳んでいたから —— つまり置換は死んだコードでした。試験を足すのではなく
その行を消しました。（この変異実行器は 2 度作り直しています。最初の 2 つは途中で落ちて、道具を
壊したままディスクに残しました。だから出荷版は `finally` で戻します。）

## 読まないもの

Issue の本文とコメントは他人が書いた文章で、この道具はエージェントに走らせる前提のものです。
だから 1 件につき **6 つの欄** —— リポジトリ・番号・題・👍・閉じた日・URL —— だけを持ち、
`extract()` が入口で残りを捨てます。単体試験 2 本と変異 M7 はそれを守るためだけに在ります。
題は表のセルに入る前に escape（`|`・`<`・`>`・改行）するので、細工した題でもセルの外に出られません。

**題が読み手に話しかけることも許していません。**題もまた他人が書いた文字列で、この一覧は
エージェントに読ませる前提だからです。開いた人への命令として読める語は切り取り、`[...]` と
表示します（リンクは元のまま）。これは最初から設計したものではありません。**自分たちの公開前の
検査が、最初に生成した一覧を突き返した**のが発端です。引っかかったのは攻撃ではなく普通の
機能要望の題（`python-poetry/poetry` の `Ability to override/[...] sub-dependencies`）でした。
だからこそ人の判断ではなく機械で切る必要があります。今回の実行で切ったのは **1 件**。その数は
一覧の冒頭に書いてあります。

通信先は `api.github.com` だけ。`GITHUB_TOKEN` を設定した場合、鍵は環境変数から読んでヘッダに
載せます。**コマンドラインに鍵を置きません。**

## 限界（そのまま書きます）

- **これは 1 回目の生成です。**「月 1 回更新」は意図であって実績ではありません。使った人はまだ
  おらず、**置いてあるリポジトリの star は 0** です。
- **全数ではなく標本です。**2 つの検索に当たるのは **408 件**、既定の実行で取り込むのは 122 件
  （1 検索あたり 3 ページ × 100 件、重なりを除く）。`--max-pages 10` で広がりますが、検索 API は
  1 検索 1,000 件で打ち止めです。
- **`Reason` 欄は GitHub の `state_reason` そのままで、少し嘘をつきます。**`wontfix` ラベルで
  拾った行には `completed` が入っていることがあります（開発元が「対応済み」で閉じたうえでラベルも
  付けた場合）。ラベル側の検索は必要です（閉じ方ではなくラベルで運用しているリポジトリを拾うため）が、
  この欄は判定として綺麗ではありません。
- **ネタ Issue・メタ Issue が入ります**（上位 9 件のうち 2 件）。抜くと「どれが本物か」の判断を
  こちらが混ぜることになるので抜きません。入力が機械的なら出力も機械的です。**読む対象であって、
  信じる対象ではありません。**
- **👍 は需要そのものではありません。**すでにその Issue を読んでいた人が 1 回押すだけの、最も安い
  需要の兆候です。古い Issue ほど集める年数が長かったという偏りもあります。
- **レート制限の待避処理はありません。**未認証の検索は 1 分 10 回までで、既定の `--sleep 2` は
  その内側です。鍵なしで `--max-pages` を 5 より大きくすると HTTP 403 が返り、その旨を表示して
  止まります。

## 誰のためのものか

次に何を作るかを決める人と、その代わりに決めるエージェントのためのものです。811 人が欲しいと言い、
コードに最も近い人たちが「作らない」と正式に表明した要望は、ただの機能案とは別の信号です。
**需要はすでに公開の場で測られていて、そのうえで扉が閉まった**ものだからです。
