# marker-drift —— 自走が止まった。仕事は済んでいた。止めたのは空白 1 個だった

2026-09-16 の朝、無人で回しているループが自分を止めました。理由は記録に残っています —— **「commit の無い単位が 3 回続いた」**。

3 回のうち 2 回は、commit されていました。印も書かれていました。門が見ていたのは `(単位運転 N)` の**完全一致**で、作業者が書いたのは `(単位運転34)` —— 半角スペースが 1 つ無い。門にとってそれは「惜しい」ではなく「印が無い」で、**印が無いことは仕事をしていないことと同じに数えられました。**

この道具は、その門が読んだのと同じ行を読み、同じ印を**厳密に**照合し、**一致しなかった行についてだけ**、5 つの軸を 1 つずつ緩めて「もう少し寛容な門なら通っていたか」を見ます。そして**どの軸が落としたのか**を名指しします。

```
$ python marker_drift.py --marker "(単位運転 {n})" --git . --at end
marker      (単位運転 {n})
lines read  917
exact       30
drift       3
no marker   884

relaxing one axis would have admitted:
  space                  3   (any run of whitespace in the marker, including none at all)

  line 11
    chore: KDPの掲載確認は手段が無いと判明・GitHubの反応を計測(単位運転34)
                                                              ^^^^^^^^^^^^
    found '(単位運転34)', relaxing space
```

Python の標準ライブラリだけで動きます。通信しません。終了コードは **0 = 取り落としなし / 1 = 取り落としあり / 2 = 走査が行われなかった**。

---

## 実測(この事業の非公開リポジトリ。commit 917 件)

| 門 | 読んだ行 | 厳密に一致 | 取り落とし | 印が無い |
|---|---:|---:|---:|---:|
| `(単位運転 {n})`(行のどこでも) | 917 | 35 | **4** | 878 |
| `(単位運転 {n})`(`--at end`) | 917 | 30 | **3** | 884 |
| `{w}: `(`--at start`。commit の接頭辞) | 917 | 915 | **0** | 2 |

読み方は 3 つあります。

1. **印を持つ 39 件のうち 4 件(10%)を、厳密な門が落としていました。**4 件とも原因は同じで、空白 1 個です。
2. **4 件のうち 1 件は、この道具の誤検出でした。**BUG-59 を直した commit が、本文の中に `(単位運転34)` を**引用**していたのです。行のどこにあっても印だと言った以上、これは道具の側の誤りです。`--at end`(門が行末で受けているなら、こちらが正しい指定)にすると 3 件になり、**その 3 件は、本線が実際に取り落とした commit と一致しました。**
3. **対照のほうが、たぶん重要です。**同じ 917 件に「行頭の `feat:` `fix:` のような接頭辞」を当てると、**取り落としは 0** です。人が毎日書いている語は揺れていません。揺れたのは、**機械が読むと決めた側の印**、毎回数字が変わるので指示文から書き写す印のほうでした。

## 5 つの軸

| 軸 | 何を許すか |
|---|---|
| `width` | 全角の英数字・記号 → ASCII(`３４` `ｕｎｉｔ` `：`) |
| `bracket` | 括弧の形 → ASCII の `( ) [ ] { } < >`(`（）` `【】` `〔〕`) |
| `dash` | ダッシュ類と長音記号 → `-`(`–` `—` `−` `ー`) |
| `case` | ASCII の大文字 → 小文字 |
| `space` | マーカーの中の空白の並びを「何個でも、0 個でも」にする |

報告に出るのは、**その行を通すために緩めなければならなかった最小の組**です。全角数字の行に `case` は付きません。

`space` だけは行ではなく**マーカーの側**を緩めます。行から空白を消す実装にすると、`--at start`(行頭で受ける門)の意味が変わってしまい、`xx feat: y` が「行頭の `feat:`」として通ってしまうからです。検査 `test_the_space_axis_never_edits_the_line` がそこを見張っています。

## できないこと(先に読んでください)

1. **印が一度も書かれなかった行は、出てきません。**冒頭の 3 連続の停止のうち 1 回は、まさにそれでした —— 上流の作業者が印を付けないまま 522 分走っていた。**この道具は「惜しい」しか見つけられず、「無い」は見つけられません。**症状は同じで原因は別です。`--list-missing N` は印の無い行を並べますが、**そのうちどれが印を持つべきだったかは言いません**(言えません)。
2. **空白の緩和が届くのは、マーカーが既に空白を持っている位置と、プレースホルダの両隣だけです。**`( unit 34)` のように、マーカーに空白が無い場所へ空白が入った行は捕まえません。これは限界として検査に書いてあります(`test_a_space_where_the_marker_has_none_is_not_caught`)。
3. **意味を見ません。**行末以外の場所で印を「引用している」行も、既定では印として数えます(上の誤検出 1 件)。門が位置を決めているなら `--at start` か `--at end` を渡してください。
4. **`{n}` と `{w}` は ASCII だけです。**Python の `\d` は `３` に一致し、`\w` は `単` に一致します。つまり `\d` で書かれた門は**全角数字を既に通しており**、この道具の厳密側を `\d` にすると、全角の揺れが「一致」として消えてしまいます。厳密側は厳密でなければ意味がありません。
5. **or を書けません。**`feat:` か `fix:` か、という門は 1 回では測れません。2 回走らせてください。
6. **直し方は言いません。**門を緩めるべきなのか、印を機械に書かせるべきなのか(こちらが本筋だと思っています)は、その門の持ち主にしか決められません。

## 使い方

```bash
# commit の件名を読む(既定は現在のディレクトリのリポジトリ)
python marker_drift.py --marker "(unit {n})" --git . --at end

# チケット ID がどれだけ揺れているか
python marker_drift.py --marker "{w}-{n}" --file CHANGELOG.md

# 何を渡してもよい
git log --pretty=%s | python marker_drift.py --marker "(unit {n})"

# 印が 1 つも無い行も 20 行だけ見る(上の「できないこと」1 を読んでから)
python marker_drift.py --marker "(unit {n})" --git . --list-missing 20

# CI から。取り落としがあれば終了コード 1
python marker_drift.py --marker "{w}-{n}" --git . --max 200 --format tsv
```

**マーカーは、門が綴っているとおりに書きます。**プレースホルダは 3 つだけ: `{n}`(ASCII の数字)・`{w}`(ASCII の語)・`{any}`。それ以外の文字はすべてそのままの文字として照合されます(正規表現ではないので、`(` は `(` です)。

`--at` は `anywhere`(既定)・`start`・`end`。**門が行頭や行末で受けているなら、必ず渡してください** —— 誤検出が減ります。上の表の 4 件 → 3 件がそれです。

## 検査

```bash
python -m unittest discover -s marker-drift -p "test_*.py"   # 85 本
python mutation_check.py                                      # わざと壊す 21 通り
```

**21 通りすべてを捕捉しています。ただし初回は 17 通りでした。**生き残った 4 つのうち 2 つが同じ形をしていて、そこが学びでした —— **`--at start` の先頭の空白を許す部分と、プレースホルダの両隣の空白を許す部分が、互いを覆っていた**のです。片方を壊しても、もう片方が同じ行を通すので、検査は落ちませんでした。2 つの守りが重なっていると、**どちらか 1 つを壊した日には誰も気づきません。**

## この道具はどこから来たか

12 ヶ月で利益 1,000 万円を作ることを目標にした事業を、AI が社長として運用しています。その運用は、毎朝ループが 1 単位ずつ仕事を取り、終わりに commit の件名へ印を書き、本線がその印を数えて「進んでいるか」を判定する形で回っています。**判定の側が 1 文字で間違えると、進んでいる日が止まった日として記録されます。**

止まった朝、オーナーからの最初の言葉はこうでした —— **「Loop otto が自走停止してる。なぜ。」**
